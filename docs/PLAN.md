# Ordered implementation plan

This is the continuation plan for the implemented source, not a substitute for it. See STATUS.md for precisely what has run.

1. **Foundation / next blocking milestone:** provision a native host with at least 100 GiB free for an initial checkout (300 GiB recommended), 32–64 GiB RAM and supported SDKs. Run the pinned official checkout, apply this overlay, GN check, build `chrome`, core tests and `browser_tests`, then launch with a fresh development profile. Fix native compile/lifecycle errors before treating any integration as delivered. Configure full Aster branding, OS IDs/icons and private profile paths together.
2. **Core productivity:** validate dual search with real providers and independent browser controls; add native saved provider settings and shortcuts, a workspace sidebar with non-destructive live workspace switching, per-workspace bookmarks and sessions, profile creation for Business, native three/four-pane layouts and explicit accessibility/theme/toolbar controls. Reuse existing Chromium services. Add browser tests for permissions, popups, downloads, tab lifetimes, private mode and multi-window persistence.
3. **Citations:** connect the tested extraction module through a narrow validated renderer bridge. Add editable metadata review, a maintained CSL processor and properly licensed APA 7/MLA 9/Chicago/Harvard/IEEE styles, output fixtures, cite/copy/in-text actions, research library, folders/tags/annotations and bibliography exports. Add PDF DOI/user-reviewed metadata without guessing.
4. **Education and business:** implement MYP research/ATL/OPVL and customizable criteria, assignment calendar and study tools; DP EE/TOK/IA/HL-SL organizers; business client/project/meeting/task/notes tools. Local storage first; no dependency on a cloud service.
5. **Data and AI:** sandboxed CSV/TSV/JSON/XLSX imports, preview/cleaning, stats/regression and charts; safe export pipeline. Add opt-in AI with provider configuration, OS keychain storage and explicit content consent for each request. Educational assistance must distinguish generated help from original coursework.
6. **Release:** native performance, security, migration, accessibility and platform review; signed/notarized macOS app/DMG and Windows executable/installer with independent install IDs, uninstaller and upgrade behavior; checksums, SBOM/licenses, smoke tests and release artifacts. Finish security-update operations before daily-use distribution.

Each phase needs actual compiled or independently executed evidence. The standalone geometry for four panes is not a four-pane browser, and default education workspace names are not completed education tools.
